一条路径怎么变成节点

课程 01 · 路由契约。学完你能对任意路径说出：落到哪个 provider、provider 收到什么字符串。

收获
手写完整 trace：Path.parse → Vfs.resolve → innerPath → VFolder/VFile。
前置
读过 core/.../Vfs.kt 的 resolve()，知道 Kotlin 的 Result。
用时
约 8 分钟。

先回忆，不要往下看

合上源码，用一句话回答这三个问题。想不起来就直接说“不知道”，这比偷看有效。

  1. Path 内部用什么表示路径？为什么不用字符串切片？
  2. 哪个函数把 scheme 变成具体的 FileProvider？
  3. 为什么 provider 的 list(path) 收不到 container:// 前缀？

回忆失败是正常的：下面每一步都对应一个你答不出的点。

五步

  1. Path.parse 字符串 → 结构化地址。 拆成 scheme / userInfo / host / port / segments。 空 segments 就是该上下文的根。
    Path.kt
  2. Vfs.resolve scheme → provider。 裸路径（以 / 开头）走 default provider；其余按 scheme 查表，查不到就返回失败。 Vfs.kt:44
  3. ResolvedProvider.innerPath URI → provider 私有路径。 file 与裸路径用 toLocalPath()，其余用 toInnerPath()（authority 变成第一段）。 ResolvedProvider.kt:9
  4. provider 操作 只认字符串。 list / stat / open 全部接收上一步的 innerPath，返回 FileEntry、ProviderStat、FileSource。
  5. VFolder / VFile 门面对象。 节点持有 (path, provider, innerPath)，对外只暴露 parent / child / listNodes / open，以及稳定的 ref()。 Folder.kt:13 
// 以 sftp://user@host:2222/home/a.txt 为例
Path.parse(...)        -> scheme=sftp, userInfo=user, host=host, port=2222,
                          segments=[home, a.txt]
Vfs.resolve(...)       -> SftpProvider
ResolvedProvider       -> innerPath = "/user@host:2222/home/a.txt"
provider.stat(inner)   -> ProviderStat(isDirectory=false, ...)
File(path, provider, innerPath)
file.ref()             -> ViewRef.Node(NodeRef.Vfs("sftp://user@host:2222/home/a.txt"),
                                       viewId="vfs", path=[])

一句话记住边界：URI 语法只活在 Vfs.resolve 之前。 越过 innerPath 之后，provider 眼里没有 scheme，只有原生路径。

三个易错点

直觉实际
provider 收到完整 URI 收到 innerPath；authority 被压成第一段，scheme 被丢弃
file:///sdcard/a 和 /sdcard/a 走两条路 都走 toLocalPath()，结果相同
zip 内容是另一个 scheme 的节点 不是。它是 ViewRef.Node(viewId="archive", path=[...])，没有 zip: scheme

4. zip 内某个文件被持久化后，它的身份是？

手写 trace

把每个输入对应的 innerPath 写进去，按 Enter 或点“核对”。错了会提示你错在哪一段。

  • container://alpine/home →
  • /storage/emulated/0 →
  • file:///sdcard/a.txt →
对完答案再看：这三题为什么能当模板

第一题练 authority 折叠（host 变成第一段）。第二题练裸路径默认 provider，输入输出同形。 第三题练 file 特殊分支：它和裸路径一样走 toLocalPath()，所以 file:///sdcard/a.txt 与 /sdcard/a.txt 得到同一个 innerPath。
