VFS 术语与路由速查

一页纸。课程里出现的每个名字都以这里为准。

路由链路

名字是什么边界
Path 不可变值对象：scheme / userInfo / host / port / segments 唯一允许解析 URI 的类型
scheme :// 之前的部分；裸路径为 null 路由键，必须全局唯一
authority userInfo@host:port 整段 进入 provider 前被折叠成 innerPath 第一段
toFullUri() 规范字符串，用于身份与持久化 toString() 即它
toInnerPath() provider 私有路径，authority 当第一段 provider 唯一见得到的路径形态
toLocalPath() 只保留 segments 的绝对路径 用于裸路径与 file scheme
ResolvedProvider (provider, path, originalUri, innerPath) 路由结果 DTO，也是 URI→innerPath 的唯一切换点
Vfs 单例路由表：scheme → FileProvider + default provider 仅它与 NodeService 能产出节点

provider 契约

名字是什么备注
FileProvider后端 SPI参数全是原生字符串；返回 Result
ProviderFeature能力位集合粗粒度，供 UI 灰化操作
DirectoryCapabilities目录级能力canCreate 等，比 feature 更细
copy(from,to,isCopy)同 provider 拷贝可走 daemon 零拷贝
copy(src,dest,isCopy)跨 provider 拷贝源是 FileSource，流式
FileSource通用可读/可写流带 size、seekable、readAt
ProviderStatstat 结果含目录标志、大小、剩余容量
FileEntry列表原始 DTOlistNodes() 会把它包成节点

对象与身份

名字是什么规则
VNode已解析节点只有 name / parent / ref()
VFile文件节点open + describe（MIME/可寻址）
VFolder目录节点listNodes / child / capabilities
NodeRef真实 Vfs 节点身份只有一个变体：Vfs(uri)
ViewRef.Node扁平视图引用root + viewId + path
viewId视图类型"vfs" 普通目录；"archive" 归档
ViewRef.Url网页位置没有 Vfs 节点，归 renderer 管
ViewRef.Session终端/DevTools归 service 管，不是文件
NodeService引用 → 节点实现：DefaultNodeService；自动进入中间归档
Navigator单标签导航状态当前节点 + 前进/后退栈 + 面包屑
ArchiveSource归档解析后端只依赖 FileSource，只读

加东西该改哪里

需求改动点不要做
新协议后端（WebDAV 等） 实现 FileProvider；在 Providers.kt 注册一次 不要动 Vfs 或加分支判断
新视图（tar、PDF 页面树） 实现 VFolder/VFile + 新 viewId + NodeService 分支 不要注册新 scheme
新操作（chmod、分享） FileProvider 默认方法或 service 层 不要为它复制一个 provider
新渲染器 render/Renderer.kt 的 Renderers/Openers 不要改 VNode 接口
持久化位置 存 ViewRef，恢复时交给 NodeService 不要存 provider 私有的 innerPath

已知摩擦点

  • Vfs.list/stat/copy 用 runBlocking 包 suspend provider，和节点 API 形成两套入口。
  • Vfs.node() 先 stat 再分类，与 NodeService.resolve() 重叠。
  • Folder.innerPathFor() 每个子节点都重建一次 ResolvedProvider，未缓存绑定。
